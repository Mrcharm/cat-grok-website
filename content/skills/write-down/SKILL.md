# write-down

## 技能定位

把"用户要写一篇文章"这类模糊需求，收口成一条可复现的写稿流水线：先想清楚再写、吃透素材、定叙事、出主稿、审美把控（通用审美基线 + 去 AI 味）、配封面与插图、对齐、导出可交付格式。

本技能不替代用户的观点与判断，只把"从素材到多平台成稿"的过程标准化，并保证**每次都有封面 + 插图**。审美把控层为通用能力，不绑定任何具体业务领域。

## 何时触发

- 用户明确要求"写篇文章 / 写个复盘 / 出一篇产品设计文 / 写博客 / 写帖子 / 写方法论"；
- 用户给了一个文件夹、文档、PPT、代码库，要求"基于此写篇文章"；
- 用户说"帮我把这个整理成文章"且目标载体是文章/博客/社媒。

不确定是否触发时，看用户是否要"成稿 + 可分发"，是则触发。

## 必须读取（首次执行）

1. `specs/write-down-output.md`：唯一产出契约（主稿 / 派生稿 / 封面 / 插图 / 导出物）；
2. `references/write-down-flow.md`：八阶段标准流程与每阶段动作；
3. `references/去AI味清单.md`：AI 痕迹词与改写准则（执行阶段 4 时加载）；
4. `references/审美通用准则.md`：正向审美基线——文字/结构/视觉的好标准与通用验收（执行阶段 0、3、4 时加载）；
5. 图片生成子技能：**封面** → 自建 imagegen-mcp（豆包 Seedream 生图，见阶段 5）；**插图** → `/ian-xiaohei-illustrations`（本地安装名，前缀 ian- 非 lan-）；架构类图（状态机/流程/金字塔）→ 手绘 SVG 保证可控可嵌入。

## 标准输入

- 用户的写稿指令 + 源材料（文件夹路径 / 文档 / PPT / 代码库 / 口述要点）；
- 用户在阶段 0 补充的：目标读者、发布平台、核心主张、坦白程度、配图风格偏好。

不要求用户预先给出大纲；大纲由本技能在阶段 0 通过反问生成并请用户确认。

## 执行流程（八阶段，详见 references/write-down-flow.md）

0. **先想清楚**：反问关键前提（读者/平台/核心主张/坦白度/图风），按 `审美通用准则` 确认审美基调（画面感强度/坦白度/视觉一致性要求），输出确认过的大纲再动笔；
1. **吃透素材**：通读源文件，区分架构事实与可讲故事，提取可引用硬证据；
2. **定叙事骨架**：选主线（弯路复盘/设计思路/核心主张最稳），技术词翻人话，定每章"带走什么"；用审美准则第 6-8 条（主线单一/渐进披露/坦白度）自检骨架；
3. **首稿 + 多平台派生**：写主稿（长文，图用 `![](xxx.svg)` 占位），同源派生公众号版（瘦身）、抖音版（短图文强钩子）；落笔时遵守审美准则第 1-5 条（带走感/画面感/人话/节奏/真实）；
4. **审美校准 + 去 AI 味**：先按 `审美通用准则` 四条通用验收（带走/画面/路人/朋友圈）过一遍，再扫 AI 痕迹词、过度排比、虚词堆叠，加第一人称吐槽与画面感；
5. **配图（每次必做）**：
   - **封面** → 调用**自建 imagegen-mcp（豆包 Seedream）**真出图：用 `hunyuan-img` venv 的 python import `ian-xiaohei-illustrations/imagegen_mcp_server`，设好 `IMAGE_GEN_*` 环境变量后调 `generate(prompt, size, n)`；size 必须 ≥1920x1920（Seedream 最小 3686400 像素），按文章分目录存 `assets/<系列>/<篇>/`；
     - **封面铁律（用户 2026-08-22 最新定调）**：封面走 imagegen-mcp（Seedream）由模型根据文章核心立意**自生成整张图**（含构图、色调、视觉符号、标题文字），不再由人工规定色调/巨字/符号/留白等具体形式。唯一硬约束如下：
       1. **去 AI 水印是唯一强制要求**：prompt 必须含"no watermark / 无AI生成标记 / 无'AI生成'角标 / 无色彩数值(#xxxx) / 无乱码中文"；生成后必须检查四角与中央，出现"AI生成""#FFxxxx""RGB()""乱码中文"等文字或半透明标记必须重出/裁剪/遮盖（Seedream 常带角标与乱码，已踩坑多次）。
       2. **不预设固定色系**：色调由模型按文章立意自定，不限定暗色/亮色/冷调/暖调。
       3. **极简优先，忌元素堆砌**：用户明确反感"元素太多太杂"的封面；优先单一主体/单一隐喻 + 大留白，避免多符号拼贴。
       4. **不出现 ian 小黑 IP**（小黑只进正文插图）。
       5. 出图前自问"小图预览 0.8 秒能否懂这篇对我有啥用"，不能则重做；若多次出图仍带水印/杂乱，再考虑 PIL 后期叠标题或纯色背景兜底。
       6. **审美升级约束（2026-08-23 起，继承 frontend-slides + 小红书爆款封面生成 的方法论能力，非调用其工具）**：封面必须按 `assets/封面审美迁移清单.md` 执行，核心纠正此前"太极简几何、无讯息、像装饰画"的问题：
          - **讯息优先（最重要）**：封面一眼讲清"这篇讲什么"，用文章核心冲突/反差/结论做视觉焦点，禁止纯装饰性抽象；
          - **适度复杂、非极简几何**：允许有层次与材质细节，不用大片留白+单一方块；
          - **靠体态/结构差异讲故事**（如瘦→臃肿→匀称表达迭代），禁止数字编号/文字（用户 2026-08-23 明确不接受数字符号）；
          - **高对比强钩子**：深场+锐利强调色，对比强烈，不温吞；
          - 字体性格仅作用于排版阶段（封面图本身不放文字，标题后期叠）；不出现 ian 小黑 IP。
     - 失败备选：若 Seedream 多次出图仍偏"场景插画/灰蒙渐变/带水印/元素杂乱/对称居中"，回退为**纯色背景 + PIL 叠排大标题**或**极简几何 SVG**兜底（仍算真出图底，非 SVG 冒充插图）。
     - **水印检测注意**：深底封面不能用 near-white 检测（整张非白会漏检），须改用"异色/亮斑异常像素"扫描四角与边缘；Seedream 对"深色背景"指令偶发执行不稳（上方变浅留白），属可接受偏差。
   - **插图** → 调用 `/ian-xiaohei-illustrations`（ian 小黑风），按该技能 shot list 出图；
   - 架构类图（状态机/流程/金字塔）→ 手绘 SVG 保证可控可嵌入；
6. **图文章对齐**：把图回贴到 Markdown 对应位置，核对图说一致；
7. **导出可交付**：SVG→PNG（用 @resvg/resvg-js，避开 cairosvg 缺系统库），Markdown→Word（python-docx，图片内嵌）；
8. **收尾与沉淀**：呈现文件 + 使用说明，必要时把新流程反哺本技能。

## 停止与结束条件

- 主稿 + 至少一种派生稿（均含 Word 导出物） + 封面 + 插图 + 导出物（Word/PNG）齐备，向用户呈现即结束；
- 用户中途要求只出大纲 / 只出某平台 / 只出图，则在对应阶段停止并交付已产部分；
- 源材料不可读或用户前提冲突且无法澄清时，停在阶段 0 说明阻塞。

## 输出边界

- 只返回契约规定的文件与呈现，不附加无关解释；
- 封面与插图必须来自对应子技能，不得用文字描述替代；
- 不臆造源材料中没有的事实；技术概念翻译可通俗，但硬证据须可回溯；
- 不把内部草稿、构建脚本、临时 PNG 当作最终交付呈现（除非用户要）。

## 硬约束

- **派单铁律（不可违背）**：封面与插图必须严格走指定来源，二者不可混用、不可互相替代、不可用文字描述或 SVG 占位替代：
  - **封面** → 唯一走**自建 imagegen-mcp（豆包 Seedream）**（用户 2026-08-22 决策：封面改 Seedream 出图，弃用原红狐 `/小红书爆款封面生成`）；
  - **插图** → 唯一调用 `/ian-xiaohei-illustrations`（本地安装名，前缀 ian- 非 lan-），维持不变；
  - 任何情况下不得把插图需求塞给封面通道，也不得把封面需求塞给插图技能。
- **封面与插图每次必做**，不可省略；
- 阶段 0 未完成大纲确认前不写首稿；
- 图片引用在 Markdown 中用相对路径 `![](文件名.svg)`，导出时再转 PNG 内嵌；
- 多平台同源派生，不为每平台重写全文；
- **所有成稿（主稿 + 每一种派生稿，含公众号版、抖音拆条版等）都必须导出 Word**（图片内嵌），不可只导主稿。抖音发文等短图文派生稿同样出 Word，方便用户直接发布或归档。
