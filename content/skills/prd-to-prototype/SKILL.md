# PRD 转交互原型（prd-to-prototype）

把产品定义变成**一个能打开就点、点哪个元素右侧就讲清楚它干嘛的单文件 HTML**。

## 0. 何时使用

- 用户说"出原型""生成 HTML 原型""做个能点的 demo""把 PRD 变成原型"。
- 用户已有 PRD（product-design 产物）、决策树（grill-me 产物）、页面清单，或仅口头描述了一个产品想法。
- 用户要的是**带功能说明的可交互原型**，而非纯视觉稿。

## 1. 输入（均可选，不强依赖）

按优先级读取，命中即用，不强制任何前置阶段：

1. **阶段2 PRD**（首选）：`*_产品需求文档_PRD_Vx.x.docx` 或其中的页面/组件编号 + 功能说明段。
2. **阶段0 决策树**：grill-me 输出的决策树 Markdown。
3. **页面清单 + 功能描述**：用户直接给的"有哪些页面、每页做什么"列表。
4. **口头/文字需求**：用户一句话描述，此时降级为通用模板生成。

**去耦原则**：即使以上全无，也可凭用户口头描述直接出 HTML。PRD 只是"让编号体系与功能说明更完整"的增强输入，不是门槛。

## 2. 输出

单个自包含 HTML 文件：`原型_Vx.x.html`（或用户指定名）。零依赖、零部署，双击即开。

### 2.1 布局结构（必须）

```
┌─────────────────────────────────────────────┐
│  顶栏：产品名（最响亮文字）+ 版本 + 原型说明开关 │
├──────────────────────────┬──────────────────┤
│  左侧：可交互原型区        │  右侧：功能说明面板 │
│  - 页面切换（tab/侧栏）    │  - 按编号列出功能   │
│  - 可点击元素带编号徽标    │  - 点击左侧→高亮+   │
│  - 点击/悬停有反馈         │    滚动定位到此说明 │
│  - 表单/弹窗/Toast 可演示  │  - 说明含：流程逻辑 │
│                           │    数据走向         │
│                           │    用户动作→系统反馈 │
│                           │    验收标准         │
└──────────────────────────┴──────────────────┘
```

> ⚠️ **布局红线（高频踩坑点）**：右侧说明面板（`.spec`）必须是 `.work` 的**同级兄弟节点**，位于 `.body` 的横向 flex 行内（rail / sidenav / work / spec 依次排列）。**绝不能**把 `.spec` 放进 `.work` 内部——否则它会作为块级元素落到工作区**底部**而非**右侧**。生成后务必目检：面板应在视口右侧、与左侧工作区并排；若出现在内容下方，说明结构插错了层级。

### 2.2 编号体系（必须）

- 每个可交互元素（按钮、表单、区域、菜单、弹窗）带 **编号徽标**，如 `F-01`、`P-02`。
- 编号与右侧说明面板一一对应。编号规则：页面用 `P-xx`，功能/组件用 `F-xx`，状态用 `S-xx`。
- 编号来源优先取 PRD 既有编号；PRD 无编号时由本技能按页面顺序生成。

### 2.3 右侧说明内容（必须，面向研发）

每个编号项至少包含以下**研发向**字段（非老板向高层价值）：

- **功能流程逻辑**：这个功能的完整流程，分步写清。
- **数据走向**：输入什么数据、流向哪个系统/接口、返回什么、存哪里。
- **用户动作 → 系统反馈**：用户做了什么操作，系统给出什么响应（含校验、报错、成功提示）。
- **验收标准**：可测试的验收点（Given/When/Then 或清单式）。

可选补充：适用角色、入口、前置条件、异常态（空/加载/失败/无权限/禁用）。

### 2.4 交互联动（必须）

- 点击左侧任意带编号元素 → 右侧对应说明项**高亮 + 平滑滚动到视口中央**。
- 右侧说明项 hover/点击 → 左侧对应元素**反向高亮**（边框/底色脉冲）。
- 提供"说明面板"显隐开关：可一键收起右侧，左侧独占全宽（纯演示模式）。
- 页面切换：左侧 tab/侧栏切页，右侧说明同步切换该页功能列表。

## 3. 视觉规范（注入 frontend-skill）

生成 HTML 时自动遵循 `frontend-skill` 的规则：
- composition-first，不堆卡片；产品原型用 calm surface 层级、强间距、少色彩、一个 action accent。
- 左侧原型与右侧说明共用一套字体/间距系统，不割裂。
- 动效克制：hover 微交互、点击高亮、面板切换过渡，不堆叠入场动画。
- 跑一遍 frontend-skill 的**反 Slop 质检段**：禁止紫渐变、三卡片、暗色网格、Inter+slate-900、豆腐块布局。

## 3.1 B 端（企业级中后台）产品原型范式（默认适用）

当用户做的是 B 端 / 企业级 / 中后台产品时，原型默认遵循以下范式（覆盖视觉、交互、设计系统三层）：

### 布局（三段式）
- **顶部模块导航**：横向切换一级模块。
- **左侧模块内菜单**：当前模块下二级功能。
- **中间工作区**：主操作区。
- 右侧叠加编号功能说明面板（本技能核心）。

### 交互母题（必须尽量覆盖）
- **列表-详情-表单三件套**：列表页（搜索/筛选 + 批量操作条 + 分页 + 异常态）、详情抽屉/页、新增/编辑表单（字段分组 + 必填 + 行内校验）。
- **批量操作**：多选 + 批量审核/删除/导出，带二次确认。
- **筛选与排序**：列表上方筛选栏，列头排序。
- **权限分层**：角色 × 资源矩阵或树形勾选；无权限显示 403/禁用态。
- **异常态矩阵**：空 / 加载中 / 失败 / 无权限 / 禁用 / 重复提交，至少覆盖正常 + 空 + 失败。

### 设计系统语言
- 参考 Ant Design / Arco / Element Plus 的企业级语汇：8px 栅格、中性灰底、单品牌 accent、统一圆角与控件尺寸。
- 不套用营销落地页的"视觉立意 / full-bleed 影像"逻辑。

### 默认页面清单建议
若用户未指定页面，B 端原型默认至少含：列表页、详情/表单页、权限配置页（体现矩阵）、设置页。

## 4. 保真度

默认中高保真（接近最终产品，含基础动效）。若用户要线框（黑白灰纯布局）或高保真（含精修视觉），按用户指定调整；未指定则中高保真。

## 5. 工作流

1. 确定输入源（PRD / 决策树 / 清单 / 口头）。
2. 提取/生成页面结构与编号体系。
3. 为每个编号项撰写研发向说明（流程/数据/动作反馈/验收）。
4. 写单文件 HTML：左侧交互 + 右侧说明 + 锚点联动 + 显隐开关。
5. 注入 frontend-skill 视觉规则，跑反 Slop 质检。
6. 交付 HTML 文件路径，简述覆盖了哪些页面与功能。

## 6. 禁止

- 不交付不可点击的静态截图冒充可交互原型。
- 不让右侧说明缺失"数据走向"或"验收标准"（研发向核心）。
- 不生成依赖外部 CDN/网络资源的 HTML（必须单文件自包含）。
- 不在未跑反 Slop 质检时交付。

## 7. 平台视觉基线（合并自 demo-skill / mrcharm-demo-skill，2026-09-01）

为 mrcharm 的数据设计平台类产品（管理台 / IDE 式工作台）做原型时，**先读视觉基线再动手，不重新发明平台风格**：

- `references/screenshots/`（10 张真实平台截图）：01-02 管理台列表页（ETL/模型设计）、03 业务弹窗、04-08 IDE 工作台（暗色总览/浅色编辑/加工节点/表关联/结果区）、09 流程设计器、10 并行流程图。
- `references/templates/platform_style_tokens.json`：管理台与 IDE 工作台两套色彩/尺寸 token。
- `checklists/原型交付自检清单.md`：交付前自检（P0：可编辑可交互、不照抄参考页、主要按钮/字段/状态/跳转在 PRD 有对应说明）。
- `sample/`：参考实现三件套（demo.html/css/js）。

**红线（来自 demo-skill）**：不做成宣传页/数据大屏/卡片堆砌；不设计只有成功态的原型；批量操作必须有差异、确认、回退；AI 长时间不能只显示"生成中"；PRD 有功能但原型无入口、或原型有按钮但 PRD 无规则 = 不合格。
