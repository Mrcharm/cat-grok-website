# JARVIS RTC 实时语音服务部署

## 上线前提

本服务是纯 HTTP 的 RTC 会话控制面，部署在 Node.js 或容器平台；实时音频由浏览器与火山引擎 RTC 房间直接传输。服务不代理或存储音频、字幕，不接入 RAG 或工具调用。

在火山引擎控制台撤销所有曾出现在聊天、截图或日志里的旧凭据，重新创建凭据。所有长期凭据只能由站点所有者直接填入托管平台的 Secret/Environment Variables 页面，不得写入仓库、工单、聊天或浏览器页面。

## 服务端环境变量

原有七项必填设置保持不变。表内仅给出名称和用途，不提供示例值。反向代理部署还需完成下方的非敏感信任边界核验。

| 名称 | 用途 |
| --- | --- |
| `RTC_APP_ID` | RTC 应用标识，用于签发短期进房 Token |
| `RTC_APP_KEY` | RTC 应用密钥，仅服务端保存 |
| `VOLC_ACCESS_KEY_ID` | 火山引擎 IAM 访问标识，仅服务端保存 |
| `VOLC_SECRET_ACCESS_KEY` | 火山引擎 IAM 访问密钥，仅服务端保存 |
| `S2S_APP_ID` | 豆包端到端语音应用标识，仅服务端保存 |
| `S2S_ACCESS_TOKEN` | 豆包端到端语音访问令牌，仅服务端保存 |
| `ALLOWED_ORIGINS` | 允许调用会话接口的网页 Origin 白名单，多个 Origin 用逗号分隔 |

## Render 代理信任边界（部署前待核）

本地直接运行默认只使用 TCP 对端 IP，忽略客户端提供的转发头。Render 平台提供的 `RENDER=true` 会选择可信代理模式；仅当 TCP 对端属于明确配置的可信代理 CIDR，才从 `X-Forwarded-For` 的右端向左跳过可信代理，取第一个不可信地址。不会取任意左端值，也不假定固定跳数。

可信范围通过可选、非密钥设置 `RTC_TRUSTED_PROXY_CIDRS` 提供，以逗号分隔。它应只包含经核验的代理范围，不是访客范围。不要填全网段、笼统的内网段，或从服务出站 IP 清单猜测入站代理范围。代码不联网获取或自动更新清单。

Render 未配置可信范围、TCP 对端不在范围内、转发头缺失/格式错误或整条链均为代理时，创建会话返回 HTTP 503 / `client_ip_unavailable`；健康检查仍可正常响应。不得临时关闭此检查来完成上线。

[Render 官方说明](https://render.com/articles/how-render-handles-ddos-attacks)确认入站经过 Cloudflare 和 Render 代理，并转发 XFF，但没有给出当前链长、逐跳清洗和可安全使用的入站 CIDR 契约。[历史反馈页](https://feedback.render.com/features/p/send-the-correct-x-forwarded-for)存在不同年份的不同描述，不能据此保证当前左端值可信。

真实部署时需向 Render 核实 TCP 对端和尾端代理的准确范围、链的追加/清洗规则及绕过入口；在受控环境以两个不同网络访客测试独立的两会话上限，并测试伪造 XFF 前缀不会更换配额桶。不得把请求头、访客 IP 或凭据写入公共日志。此项尚未实测，因此当前不宣称可直接上线。

## 安装与启动

仓库固定使用与 `pnpm@11.9.0` 兼容的 Node.js 运行时，并且只允许 esbuild 执行依赖安装脚本。Render 安装和启动命令分别为：

```text
pnpm install --frozen-lockfile
pnpm start:voice
```

也可以从仓库根目录构建 `Dockerfile`。容器以非 root 用户启动，只安装生产依赖。

## 健康检查与两阶段会话

服务启动后先请求健康检查：

```text
GET https://<服务域名>/healthz
```

预期 HTTP 200，正文只有：

```json
{"ok":true}
```

健康检查只证明进程可访问，不证明 RTC、IAM 或豆包鉴权成功。完整会话必须按以下顺序验证：

1. 网页向 `POST /rtc/session` 申请短期 RTC 会话。
2. 网页使用响应中的短期 Token 加入 RTC 房间。
3. 入房成功后调用 `POST /rtc/session/:sessionId/start`，启动 VoiceChat 任务。
4. 用户主动结束或离开页面时调用 `DELETE /rtc/session/:sessionId`，停止任务并释放麦克风。

旧 `/voice` WebSocket 路径已停用，并明确返回 404。健康检查或静态测试通过都不能替代真实 `StartVoiceChat`、中文多轮对话、字幕、远端音频、打断和清理验收。

## 连接首页

后端完成真实验收前，不修改首页当前为空的 `data-voice-endpoint`。后端确认健康且会话链路可用后，再把这里设置为服务的公开 HTTPS Origin；不要附加旧 `/voice` 路径。该 Origin 是公开信息，页面仍不得包含任何长期凭据。

修改后依次执行：

```text
pnpm check
```

最后使用真实浏览器验证首次点击授权、连续三轮中文对话、快速字幕、远端音频、语音打断、主动停止、权限拒绝、移动端布局和离开页面后的麦克风释放。

## 日志与故障定位

每次 Start/Stop 上游请求默认最多等待 10 秒，覆盖响应头和完整正文。开始请求发出前即保留任务标识；响应丢失、超时或解析失败后，不推断远端没有任务，而是自动补偿 Stop。失败会话不能再次 Start，应在清理完成后创建新会话。

DELETE 或到期 Stop 失败后，服务端保留标识和 IP 配额，并按 1 秒、2 秒、5 秒、30 秒重试，之后每 5 分钟继续尝试；同一会话只允许一个停止请求和一个清理定时器。只有成功 Stop 才释放尝试启动过的会话。尚未核实官方“任务不存在”错误映射，因此任何错误响应都不会被猜测为成功。

浏览器按会话 `expiresAt`（本地最多 15 分钟）主动结束，或在 SDK `onError` 的终止事件中清理；会离房、停止采集并销毁引擎，不续期绕过限制。定时器带会话代次保护，旧会话不能结束新会话。

清理队列与配额目前在单进程内存中，不跨实例共享，也不跨进程重启持久化。此版本仅适用于单实例验收；停止失败时不要靠重启来“释放配额”。进程退出/崩溃后的远端任务需在控制台核验，不能把本地进程结束视为远端停止证据。

生产日志只允许记录随机请求 ID、公开错误码、连接状态和耗时。禁止记录请求头、环境变量、签名材料、上游原始响应、音频内容或字幕。鉴权失败时只在火山引擎控制台核对应用、资源开通和权限关系，不要把任何凭据复制到日志中。
