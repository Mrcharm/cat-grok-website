# NotebookLM 学习卡片与自动周报设计

日期：2026-07-25
目标网址：https://mrcharm.github.io/cat-grok-website/

## 1. 目标

在不破坏现有 30 天成长计划的前提下，为“今日行动”增加一条独立的每日学习轨道：

1. 2026-07-26 至 2026-07-28 完成一次三天高强度学习冲刺。
2. 必修内容覆盖 OpenSpec、gstack、Spec Kit、vibe-coding-cn。
3. 知识卡片正文必须来自猫哥的 NotebookLM 笔记本，不能用模型常识或外部文章补写。
4. 除四个必修仓库外，NotebookLM 中可检索到的其他主题也要进入长期知识卡片库。
5. 每周五 18:30（Asia/Shanghai）根据可公开证据生成并发布一篇猫哥周报。

## 2. 成功标准

### 2.1 三天学习

三天后达到“同事交流级掌握”：

- 能脱稿说明四个项目的一句话定位。
- 能解释四者解决的问题、核心工作流、适用边界和主要区别。
- 能说明 OpenSpec 与 Spec Kit 的选型差异。
- 能说明 gstack 为什么不是规格框架的简单替代品。
- 能说明 vibe-coding-cn 的 Prompt、Skill、Context、Quality Gate 与工程闭环。
- 能针对一个银行数据研发场景给出组合方案，并回答至少 12 个常见追问。

### 2.2 知识卡片

- 每张正式卡片都有 NotebookLM 生成证据。
- 卡片记录笔记本、生成日期、原始查询和 NotebookLM 回答快照。
- 没有 NotebookLM 回答证据的内容不得进入正式卡片。
- 必修仓库缺少可用 NotebookLM 来源时，先补齐或修复来源，再生成对应卡片。
- NotebookLM 其他主题按主题簇进入知识库，不被四个仓库范围截断。

### 2.3 周报

- 周报只陈述有公开证据的事实。
- 私人证据、私人复盘和公司敏感内容不自动进入公开文章。
- 缺少当周公开素材时不编造、不发布空洞文章，自动任务应停止并通知猫哥。
- 发布必须通过构建、测试、Git 提交、推送和线上页面验收。

## 3. NotebookLM 来源门禁

当前激活笔记本：

- 名称：Vibe Coding工程方法论
- NotebookLM URL：`https://notebooklm.google.com/notebook/ad0a68f5-6136-426e-a142-11a2b86e2395`

实施时执行以下来源门禁：

1. 获取并保存 NotebookLM 全量主题地图。
2. 对四个必修仓库分别发起独立查询，禁止改答其他项目。
3. 每个项目至少得到定位、核心概念、工作流、适用边界、误区和问答六类内容。
4. 保存原始 NotebookLM 回答快照到不参与网页渲染的研究目录。
5. 卡片生成器只允许读取这些回答快照。
6. 若 OpenSpec 或 Spec Kit 仍无法产生有效回答，先在 NotebookLM 中确认或补充来源，不能用 GitHub README 替代卡片正文。
7. 官方 GitHub 链接可以作为延伸阅读，但不得成为知识卡正文的隐性来源。

来源字段最少包括：

- `notebook`
- `notebookUrl`
- `query`
- `queriedAt`
- `answerSnapshot`
- `citationMarkers`
- `sourceLabels`

## 4. 信息架构

### 4.1 行动页

保留现有 30 天任务、月历和看板，新增：

- “本周学习”概览卡。
- 日历日期上的“学习”标记。
- 独立学习详情对话框。
- 学习卡片、闭卷自测、打卡证据与复习状态。
- “本周可公开摘要”和“导出周报素材”区域。

同一天可以同时有一个成长任务和一个学习任务，两个进度互不覆盖。

### 4.2 知识库

新增公开知识卡片页，分为：

1. 三天必修冲刺。
2. 四个仓库专题。
3. NotebookLM 其他主题。
4. 对比与选型。
5. 常见问答。

每张卡片支持：

- 正面问题。
- 背面答案。
- 为什么重要。
- 常见误区。
- 来源说明。
- “会讲 / 需复习”本地状态。

### 4.3 写作与周报

周报作为“写作”中的独立类别。文章结构固定为：

1. 本周一句话。
2. 做成了什么。
3. 学到了什么。
4. 哪个判断被推翻。
5. 下周唯一重点。
6. 可公开的证据链接。

## 5. 三天课程

### Day 1：全景认知与方法论

时间：75 分钟。

- 认识四个项目分别处于方法论、规格层和执行层的哪个位置。
- 掌握 vibe-coding-cn 的 Prompt、Skill、Context、Quality Gate、工程闭环。
- 建立四者全景图。
- 交付：1 分钟脱稿定位说明。

### Day 2：OpenSpec 与 Spec Kit

时间：90 分钟。

- OpenSpec 的 specs、changes、delta specs、artifacts、archive。
- Spec Kit 的 constitution、specify、clarify、plan、tasks、analyze、implement。
- 用同一银行数据研发需求映射两套流程。
- 交付：差异表和选型理由。

### Day 3：gstack 与综合答辩

时间：90 分钟。

- gstack 的 Think → Plan → Build → Review → Test → Ship → Reflect。
- office-hours、autoplan、review、qa、ship、retro 的职责。
- 形成四者组合决策树。
- 完成 12 道同事追问题和 5 分钟口述录音。

## 6. 数据与状态

公开数据：

- `data/learning-sprints.json`：三天课程和日期。
- `data/learning-cards.json`：NotebookLM 生成的公开知识卡片。
- `data/learning-sources.json`：脱敏后的来源追溯信息。

研究证据：

- `research/notebooklm/`：NotebookLM 原始回答快照，不直接渲染。

本地私有状态：

- 学习卡片是否展开。
- “会讲 / 需复习”状态。
- 每日自测答案。
- 打卡证据和私人复盘。

行动任务状态继续使用现有存储；学习状态使用独立版本化存储，避免破坏既有备份。

## 7. 周报数据流

静态网站不能让后台任务直接读取浏览器 localStorage，因此采用显式公开边界：

1. 猫哥在行动页填写“本周可公开摘要”。
2. 网站导出 `mrcharm-weekly-input-YYYY-MM-DD.json`。
3. 导出文件只包含明确允许公开的摘要、完成任务标题、学习完成状态和公开链接。
4. 私人证据、自测答案和复盘原文不进入导出。
5. 周五自动任务读取最近七天内最新的周报素材和网站 Git 提交记录。
6. 自动任务生成周报 Markdown，执行隐私与事实检查。
7. 工作区不干净、素材缺失、测试失败或远端冲突时停止发布并通知猫哥。
8. 条件满足时提交、推送并验证公开页面。

## 8. 自动化

创建本地 Codex 周期任务：

- 名称：猫哥每周成长周报
- 时间：每周五 18:30
- 时区：Asia/Shanghai
- 项目：cat-grok-website
- 运行位置：本地项目

自动任务不得：

- 猜测未记录的工作。
- 读取或发布浏览器私人字段。
- 覆盖未提交的本地修改。
- 在测试失败时推送。
- 省略线上验收。

## 9. 测试

至少覆盖：

- 所有正式卡片都有 NotebookLM 来源字段。
- 四个必修仓库均有卡片和问答。
- NotebookLM 其他主题至少形成一个额外主题簇。
- 日历能同时展示成长任务与学习任务。
- 学习状态和行动状态相互隔离。
- 卡片键盘可操作，答案默认折叠。
- 周报导出不包含私人证据、私人复盘和自测答案。
- 周报素材缺失时发布流程失败关闭。
- 周报文章能进入写作索引和首页近期记录。
- 移动端不出现横向滚动。

## 10. 非目标

- 不把 NotebookLM 登录信息或浏览器状态提交到仓库。
- 不在公开网站中嵌入 NotebookLM 私有页面。
- 不给静态网站增加 GitHub Token。
- 不引入账号系统或服务端数据库。
- 不承诺三天内掌握四个仓库全部源码。
- 不让周报自动化突破“精选公开”的隐私原则。
