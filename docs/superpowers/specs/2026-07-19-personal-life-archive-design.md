# 猫哥个人生涯与生活学习记录站融合设计

日期：2026-07-19
目标网址：https://mrcharm.github.io/cat-grok-website/

## 1. 目标

将现有“智能体团队养成日记”网站融合升级为猫哥长期使用的个人记录入口。网站以猫哥本人为主角，持续记录职业发展、学习认知、生活体验、作品实践，以及通往 2031 年的阶段进度。

同一网址同时承担两个角色：

1. 面向访客的精选公开个人杂志。
2. 面向猫哥本人的每日行动舱。

智能体团队保留为作品档案之一，不再作为整站身份中心。所有升级都发布到原 GitHub Pages 地址，不创建第二个公开站点。

## 2. 成功标准

- 访客在首页第一屏能确认网站主人是猫哥，而不是一个智能体团队。
- 访客能理解猫哥当前的职业方向、长期目标和职业/学习/生活三条主线。
- 原站已有的智能体团队、成长里程碑、飞书 Agent 文章、AI 科普、技能与工具内容仍可访问。
- 公开区只呈现经过选择的文章、月度目标、每周进展和已完成成果。
- 猫哥能在“今日行动”中看到当天唯一任务、执行理由、30 分钟步骤、资料、完成标准和复盘入口。
- 每日完成状态、证据和复盘默认只保存在当前浏览器，不上传到 GitHub。
- 网站在手机和桌面端均可使用，键盘操作、颜色对比和正文阅读达到基本无障碍要求。
- 新文章可以从 Markdown 源文件生成公开页面，猫哥不需要直接维护网页代码。

## 3. 非目标

第一版不包含：

- 网站内 AI 教练对话。
- 登录账号、数据库或真正的私人后台。
- 自动读取公司系统、日历、交易账户或家庭数据。
- 自动根据昨日表现修改任务计划。
- 将未脱敏的公司项目、客户信息、家庭隐私或投资账户数据放到公开仓库。

## 4. 内容与隐私原则

### 4.1 精选公开

公开内容包括：

- 2031 长期方向。
- 2026 年度目标。
- 当前月度目标。
- 每周精选进展。
- 已完成的阶段成果。
- 职业、学习、生活文章。
- 脱敏后的作品档案。

不公开：

- 私人复盘原文。
- 每日完成证据。
- 具体卡点和敏感上下文。
- 未经猫哥确认的生活、公司或投资信息。

### 4.2 静态站点边界

GitHub Pages 没有登录保护。每日任务定义会随网站文件公开，因此任务描述必须脱敏。完成状态、证据和复盘使用浏览器本地存储，不进入公开仓库。若未来需要真正私密的跨设备同步，再独立设计登录和服务端存储。

## 5. 信息架构

主导航：

1. 首页
2. 人生轨迹
3. 写作
4. 作品
5. 关于我
6. 今日行动

### 5.1 首页

首页按以下顺序组织：

1. **猫哥本人**：一句话身份、当前阶段、正在解决的问题、通往 2031 的长期主题。
2. **此刻的我**：当前职业方向、近期学习主题、生活关注点、本月重点。
3. **三条人生线**：职业成长、学习认知、生活体验。
4. **通往 2031**：五年方向、今年目标、本月里程碑、每周精选进展。
5. **近期记录**：混合展示 AI 学习、产品实践、产业思考和生活感悟。
6. **作品档案**：智能体团队、飞书 Agent、数据研发 AI Copilot 等项目。
7. **关于我**：能力组合、经历沉淀、价值观和外部入口。

### 5.2 人生轨迹

按时间展示职业、学习、生活节点。每个节点至少包含日期、所属主线、事件、得到的认知和关联内容。五年目标是未来轨迹的一部分，不单独变成一张孤立的规划表。

### 5.3 写作

文章分为四类：

- 职业与产品
- 学习与认知
- 生活与关系
- 产业研究

文章列表支持按分类查看，文章详情显示日期、摘要、正文、关联目标和关联作品。

### 5.4 作品

作品页展示项目名称、问题、猫哥的角色、方法、结果、限制和相关记录。

智能体团队作为现有代表作品保留以下内容：

- 团队养成日记和成长里程碑。
- 四位智能体介绍。
- 团队理念。
- Claw / AI 科普内容。
- 技能与工具。
- 飞书 Agent 实践文章。

这些内容进入作品详情或关联文章，不在首页占据主叙事位置。

### 5.5 今日行动舱

行动舱包含：

- 今日唯一任务。
- 为什么今天做。
- 30 分钟执行步骤。
- 对应资料和方法论。
- 完成标准。
- 计时器。
- 证据和复盘输入框。
- 月历。
- 接下来、进行中、已完成三列看板。
- 进度导出与导入备份。

若当天没有匹配任务，显示下一个未完成任务；全部任务完成后显示月度复盘入口，不重复派发旧任务。

## 6. 内容更新流程

猫哥不直接维护网页：

1. 猫哥将想法、语音整理、草稿或素材交给 Codex。
2. Codex确认公开范围并脱敏。
3. Codex整理为 Markdown，补齐标题、摘要、分类、日期、关联目标和关联作品。
4. 构建流程生成公开页面和索引。
5. Codex完成本地检查并发布到原 GitHub Pages 地址。

私人执行到公开成长的转换流程：

1. 每天在行动舱完成任务并留下私人证据。
2. 每周由猫哥选择值得公开的结果。
3. Codex将其编辑成每周进展、文章或作品里程碑。
4. 公开首页只显示整理后的版本。

## 7. 技术架构

网站保持无服务端的静态多页面架构，避免引入账号、数据库和持续运维。

组件边界：

- **内容源**：Markdown 文章、公开进展、作品和目标数据。
- **构建层**：将 Markdown 与结构化数据生成静态 HTML 和索引。
- **公开展示层**：首页、人生轨迹、写作、作品和关于我。
- **行动层**：读取静态任务定义，使用浏览器本地存储保存执行状态。
- **发布层**：生成的静态文件提交到现有仓库，由 GitHub Pages 服务。

新内容以 Markdown 为权威源；生成后的页面也提交到仓库，使 GitHub Pages 无需运行服务端。已有 HTML 文章保持原链接，后续逐篇迁移，不在本次融合中强制重写。

建议的源文件边界：

- `content/posts/`：文章 Markdown。
- `content/projects/`：作品 Markdown。
- `data/profile.json`：个人简介和三条人生线。
- `data/roadmap.json`：2031、年度、月度和每周公开进展。
- `data/tasks.json`：脱敏后的每日任务和执行策略。
- `assets/`：站点样式、脚本和图片。
- `blog/`、`projects/`：构建生成的公开页面。

每个模块只依赖结构化输入，不从其他页面 DOM 抽取内容。

## 8. 视觉设计

视觉基调：明亮、亲切、有活力、轻卡通，但不幼稚。

- 主色使用清爽蓝色，不使用紫色作为主色。
- 背景使用浅蓝白或柔和中性色。
- 珊瑚橙、暖黄、薄荷绿作为辅助色。
- 卡片使用 18–24px 圆角、轻阴影和清楚的层级。
- 猫咪符号、表情和简单 CSS 图形用于增加人格感，不喧宾夺主。
- 正文保持高对比、合适行长和充足留白。
- 行动舱沿用同一套蓝色视觉语言，更像陪伴式工具，不像企业绩效仪表盘。
- 避免大面积黑色、霓虹科技感、蓝紫渐变和过度密集的仪表盘。

## 9. 原站融合策略

融合遵循“内容保留、层级重排、视觉统一”：

| 原站内容 | 融合后位置 |
| --- | --- |
| 猫哥身份和外部链接 | 首页第一屏、关于我 |
| 智能体团队成长里程碑 | 作品详情 |
| 四位智能体介绍 | 作品详情 |
| 团队理念 | 作品详情 |
| Claw / AI 科普 | 学习文章、作品关联内容 |
| 技能商店 | 作品详情或技能与工具板块 |
| 飞书 Agent 文章 | 保留原链接，并进入写作索引 |
| 工具箱 | 作品/工具索引 |
| 留言与交流入口 | 页脚或关于我 |

融合发布覆盖原首页，但不删除仍有价值的子页面和文章链接。

## 10. 状态与错误处理

- 本地存储为空：显示全部任务为未开始。
- 本地存储损坏：保留原始值的下载入口，确认后重置为空状态。
- 浏览器禁用本地存储：允许查看任务，但明确提示进度无法持久保存。
- 任务数据缺失：显示“本月计划尚未发布”，不渲染空看板。
- 文章或作品数据不完整：构建失败并指出文件，不发布半成品页面。
- 外部链接失效：不影响主体页面加载；发布检查列出失败链接。
- 新版数据结构升级：以版本号迁移本地数据，不静默丢弃历史记录。

## 11. 验收与测试

### 11.1 内容验收

- 首页第一屏只讲猫哥本人。
- 职业、学习、生活三条主线均有真实内容。
- 2031、年度、月度、每周四层目标关系清楚。
- 原站列入融合表的内容均能从新站访问。
- 飞书 Agent 文章原链接继续工作。

### 11.2 行动舱验收

- 正确显示当天任务或下一个未完成任务。
- 任务理由、步骤、资料、完成标准齐全。
- 勾选、证据、完成状态在刷新后保留。
- 看板与日历同步更新。
- 导出后可用导入恢复同一状态。
- 完成全部任务后进入月度复盘状态。

### 11.3 视觉与可用性验收

- 桌面、平板和手机三种宽度无横向溢出。
- 所有主要操作可用键盘完成。
- 聚焦状态可见，按钮和链接有清楚名称。
- 正文和按钮颜色达到可读对比。
- `prefers-reduced-motion` 下禁用非必要动效。
- GitHub Pages 子路径 `/cat-grok-website/` 下所有相对资源、文章和分享图片可访问。

### 11.4 发布验收

- 本地构建无错误。
- JavaScript 语法检查通过。
- 公开页面与资源返回成功状态。
- 线上首页包含人生轨迹、写作、作品、关于我和今日行动入口。
- 线上行动舱可以完成一条测试任务并在刷新后恢复状态。
- 发布后检查桌面和手机视口，确认布局与蓝色视觉方向一致。

## 12. 最终设计结论

采用“个人杂志 + 私人行动舱”方案：猫哥本人是唯一主叙事，公开展示经过整理的职业、学习、生活和作品记录；行动舱用固定任务和执行策略推动每日行动。视觉延续原站的明亮、轻松和卡通感，但以蓝色替换紫色，并提升阅读与长期维护能力。全部内容融合到现有 GitHub Pages 网址。
