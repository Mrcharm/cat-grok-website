# JARVIS 首页豆包实时语音设计

## 目标

把首页当前的“浏览器语音识别 + 本地固定回复 + 系统语音朗读”替换为豆包端到端实时语音对话。用户首次进入首页点击一次“开始语音对话”并授权麦克风，之后保持连续会话，可以直接说话、接收流式语音回复并在回复过程中打断。

## 已确认的用户体验

1. 首页载入后不自动申请麦克风权限，语音区显示“JARVIS 已就绪”。
2. 用户点击一次“开始语音对话”，同时完成麦克风授权和浏览器音频播放解锁。
3. 建连成功后按钮进入“聆听中”，用户无需重复点击即可连续对话。
4. JARVIS 回复时流式播放豆包返回的语音，并同步展示用户和助手字幕。
5. 用户在回复播放期间重新开口时，立即停止当前播放并向服务端发送打断事件。
6. 用户可以主动结束会话。页面离开、隐藏过久或网络断开时释放麦克风与连接。
7. 文本输入继续保留，并通过同一个实时会话发送；不再使用本地预设回复。

## 方案比较

### 方案 A：独立 Node.js WebSocket 代理（采用）

GitHub Pages 继续托管静态网站，新增一个独立 Node.js 服务代理豆包 WebSocket。豆包凭据只存在托管平台的服务端环境变量中。这个方案能完整转发二进制音频帧，便于实现鉴权、连接治理、限流和日志脱敏。

代价是需要额外部署一个长期可用的服务，并配置其公开 `wss://` 地址。

### 方案 B：浏览器直连豆包（否决）

实现最少，但会向任何访客暴露 Access Token，并且浏览器 WebSocket 无法像服务端客户端一样自由设置鉴权请求头。不能用于公开网站。

### 方案 C：非实时 HTTP 语音链路（否决）

可以把录音上传后依次执行识别、对话、合成，部署简单，但无法达到连续交流、低延时和随时打断的目标。

## 系统结构

### 首页语音控制器

新增独立的首页语音模块，负责：

- 获取和释放麦克风权限；
- 把浏览器音频转换为服务要求的 PCM 数据块；
- 管理网站到代理服务的 WebSocket；
- 播放服务端返回的流式音频；
- 管理“未开始、连接中、聆听中、回复中、重连中、已结束、错误”状态；
- 渲染实时字幕和用户可理解的错误信息。

首页只保存代理服务 URL，不包含 App ID、Access Token、Secret Key 或任何可恢复凭据。

### WebSocket 代理

新增独立 Node.js 服务，负责：

- 校验网页来源，只接受正式站点与本地开发地址；
- 对每个浏览器会话建立一条豆包实时语音上游连接；
- 从环境变量读取豆包 App ID、Access Token、Secret Key 和模型资源标识；
- 按豆包官方协议构造鉴权和会话初始化消息；
- 双向转发音频、字幕、状态、打断和结束事件；
- 限制单 IP 并发、会话时长和消息大小；
- 日志只记录请求 ID、状态码和耗时，不记录音频正文、字幕或凭据。

服务使用通用 Node.js 部署结构，首选支持持久 WebSocket 的容器型托管平台。不会使用不保证长连接的普通函数服务。

## 浏览器与代理之间的协议

控制消息采用 JSON：

- `client.start`：浏览器开始会话；
- `client.text`：发送文本输入；
- `client.interrupt`：用户打断助手；
- `client.stop`：用户主动结束；
- `server.ready`：上游建连并初始化成功；
- `server.transcript`：用户或助手的增量/最终字幕；
- `server.state`：会话状态变化；
- `server.error`：可安全展示的错误代码和提示。

音频数据使用 WebSocket 二进制帧，避免 Base64 增加体积和延时。代理负责把站内协议映射到豆包官方二进制协议，不把供应商协议细节扩散到页面 UI 代码。

## 安全设计

- 已在对话中出现的旧凭据视为泄露，不进入仓库、测试快照、日志或部署配置。
- 上线前必须在火山引擎控制台轮换凭据，并由站点所有者直接配置到托管平台环境变量。
- 代理启用来源白名单、会话时长上限、消息大小上限和基础限流，降低公开网站额度被盗刷的风险。
- 不录制、不持久化用户音频和字幕。
- 服务端错误经过映射后再返回浏览器，禁止回传上游请求头或原始凭据。

## 故障与降级

- 麦克风被拒绝：保留文字输入，明确提示如何重新授权。
- 豆包鉴权或资源未开通：结束实时会话并显示配置错误，不回退到本地假回复。
- 临时断网：进行次数受限的短重连；重连期间不缓存或补传用户私密音频。
- 浏览器不支持所需音频能力：保留文字入口并说明浏览器兼容性要求。
- 背景音乐与实时语音冲突：开始语音会话时暂停背景音乐，结束后不自动恢复，交由用户决定。

## 验收标准

1. 仓库扫描确认没有豆包凭据及其片段。
2. 首次点击后浏览器请求麦克风权限；拒绝权限时页面仍可文字输入。
3. 代理完成真实豆包鉴权后，页面才进入“聆听中”。
4. 使用真实账户完成至少三轮连续中文语音对话，回复音频为边接收边播放。
5. 助手播报过程中开口可以停止当前播报并进入下一轮。
6. 实时显示双方字幕，增量字幕不会重复堆叠。
7. 主动结束、页面关闭和异常断线都会释放麦克风及上下游连接。
8. 现有四页导航、首页视觉布局、文字输入和移动端布局不回归。
9. 内容校验、自动化测试、构建、烟雾检查全部通过，生成页面与构建输出一致。
10. 线上 GitHub Pages 和代理服务均通过真实浏览器验证后才宣布完成。

## 实施边界

本次只接入首页的一对一实时语音，不增加账户体系、对话持久化、知识库检索、付费、多人房间或音色复刻。模型资源标识从服务端环境变量读取，并以火山引擎控制台中已开通资源与真实握手结果为最终依据。
